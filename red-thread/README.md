# 红线算法

一支约 3 分 15 秒的竖屏科普短片，讲 1962 年盖尔和沙普利的「稳定婚姻」算法（延迟接受算法）：
同样八个人、同样的心意，只换**谁先开口**，结局就完全不同；而且先开口的一方，总能拿到所有稳定结果里对自己最好的那个。

**成片在 `output/`，发布文案在 [`publish.md`](publish.md)，带时间码的旁白与事实核查在 [`script.md`](script.md)。**

## 这类视频是怎么做出来的

不是一句提示词生成的，而是一套「先定规范、再写代码、看图迭代」的流程：

1. **先写旁白，再做画面。** `src/script.py` 是唯一事实来源：每句旁白、停顿、高亮词都在这里。画面上每个动作都锚定在某句话的某个字上（`charT('E5', '阿山被挤走')`），改一句话，整片自动重新对齐。
2. **一个比喻贯穿到底。** 月老牵红线：配对是红线，「暂时留下」是虚线加一枚「暂」字章，被拒绝是红线崩断，私奔是两人跑到一起。所有视觉元素都从这个比喻里来。
3. **统一的视觉系统。** 宣纸底、墨色、朱砂红，只有红线一个强调色；八个 Q 版古风小人用同一个模板，只换发型、衣色和表情；每人一个专属色，从名章到偏好卡片都用同一种颜色。
4. **演示是真算法跑出来的。** `src/render/match.js` 里是偏好表和 Gale–Shapley 算法本身，每一轮谁向谁表白、谁被拒、谁被挤走，都是程序算出来再画出来的。偏好表是用脚本从大量随机样例里挑的：男生先开口时是一串 4 轮的「连锁反应」，女生先开口时 1 轮就结束，而且两次结果没有一对相同（这组偏好恰好只有这两个稳定配对）。代码里有自检：如果有人改了偏好表，和旁白对不上就直接报错。
5. **看图迭代。** `node main.js --still 12.5,40` 渲染任意时刻的单帧，几十个关键帧排成样张逐一检查：对齐、遮挡、字号、风格是否一致。

## 全部由代码生成

| 环节 | 做法 |
|---|---|
| 旁白 | 离线 TTS：Kokoro v1.1-zh（sherpa-onnx），男声 #62；每句用 SenseVoice 语音识别回听，不达标就换语速重合成。人名用「阿山 / 小梨」这样的双字名，因为单字「荷、梨、杏」听起来和「和、离、性」分不清 |
| 字幕 | 按标点切块，时间吸附到音频里真实的停顿上；关键词高亮 |
| 画面 | Node + `@napi-rs/canvas` 逐帧绘制 1080×1920@30fps，14 个场景；`cast → menfirst → result1 → womenfirst` 共用同一块「棋盘」，场景之间不做淡入淡出 |
| 配乐 | numpy/scipy 合成的原创配乐：D 宫五声音阶 + Karplus–Strong 拨弦（古筝感），随剧情分段（夜色 → 俏皮 → 思考 → 连锁反应 → 揭晓 → 温暖 → 尾声），贯穿一个五音「红线」动机 |
| 音效 | 红线拉紧、崩断、打结、印章、多米诺……由渲染器按画面事件导出时间点后合成 |
| 混音 | 旁白驱动的音乐闪避，两遍 loudnorm 到 -14 LUFS / -1.5 dBTP |

## 重新生成

```bash
cd red-thread
npm install
pip install sherpa-onnx numpy scipy
src/fetch_assets.sh     # 字体与离线语音模型（约 1 GB，不入库；已有 ../neural-network-history/assets 可直接软链接过来）
src/build.sh            # → output/
```

换成外部配音（例如冬瓜配音导出的 MP3）：`NARRATION="dubbing/旁白.mp3" src/build.sh`，流程同《神经网络往事》。

预览单帧：`cd src/render && node main.js --still 98.5,141`（输出到 `build/stills/`）。
查看算法每一轮：`node src/render/match.js`。
